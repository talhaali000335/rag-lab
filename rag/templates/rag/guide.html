1. What is RAG?

A language model only knows what it was trained on. Retrieval-augmented generation fixes that: before answering, the app retrieves relevant passages from your own documents, then generates an answer using only those passages. Better answers, fresh data, and a source you can point to.

The basic loop: question → retrieve passages → generate answer from passages → check the answer is supported. The six architectures below change what happens in between.

2. The six architectures

TypeUse it whenScreen
MultimodalAnswers live in images, audio or text/lab/multimodal/
AdvancedPlain search returns noisy results: add rewrite, re-rank, filter/lab/advanced/
AdaptiveQuestions vary: skip retrieval, retrieve once, or break apart/lab/adaptive/

Start with Advanced RAG for most real products. Add the others only when you can name the failure they fix.

3. Run it on your computer

1

Install Python 3.12 and create an environment

cd rag_lab
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
2

Create your settings file

cp .env.example .env
export $(grep -v '^#' .env | xargs)   # loads the variables into your shell
3

Create the database, run the tests, start the server

python manage.py migrate
python manage.py test
python manage.py runserver

Open http://127.0.0.1:8000. Pick a tab, click an example question, and read the numbered trace: every box is one stage of that architecture.

4

Call it as an API

curl -X POST http://127.0.0.1:8000/api/ask/ \
  -H "X-API-Key: dev-api-key" -H "Content-Type: application/json" \
  -d '{"question":"What is the refund policy?","pipeline":"advanced"}'

Or with Docker and Postgres: docker compose up --build.

5. How LangGraph orchestrates a request

LangGraph runs your steps as a graph of small functions that share one state dictionary. Each function returns only the keys it changes. A conditional edge chooses the next step, which is how a blocked request skips retrieval.

START → input_guard ─┬─ blocked → refuse ───────────────────→ END
                     └─ ok ────→ run_pipeline → generate → output_guard → END

Open rag/orchestrator.py: build_graph() is 12 lines. To add a step (say, a cache lookup), write a function (state) → dict, call g.add_node, and wire it with add_edge.

Why a graph and not plain function calls? One place guarantees every pipeline, including future ones, passes both guardrails. Nobody can forget them.

Try it: the Guardrails screen shows attacks being blocked, and on any lab screen asking "When does staff payroll run?" gives different results for public and staff.

Regex rules are a first wall, not a complete defence. Before real users: add a classifier layer (Amazon Bedrock Guardrails or Llama Guard), and take the caller's role from the logged-in user. The demo reads it from the URL so you can see the effect.

7. MLOps: keep quality from drifting

1

Log everything useful

Every question writes a QueryLog row: pipeline, latency, groundedness, blocked or not. The MLOps screen charts it as a table. Logs go to stdout, which CloudWatch collects on AWS.

2

Keep a golden question set

rag/eval_set.py pairs questions with the document that must be retrieved. Add real user questions that went wrong.

3

Make quality a build gate

python manage.py run_eval --min-hit-rate 0.8

It prints hit-rate and groundedness per pipeline, saves an EvalRun, and exits with an error if quality drops. .github/workflows/ci.yml runs it before deploying.

4

Watch it in production

Create CloudWatch alarms on: 5xx rate, p95 latency, and a drop in average groundedness or a rise in blocked requests. Roll back by redeploying the previous task definition.

8. Deploy to AWS (ECS Fargate)

Costs money. Use a small account, delete resources when finished. Replace REGION and ACCOUNT_ID.

1

Container registry

aws ecr create-repository --repository-name rag-lab
aws ecr get-login-password | docker login --username AWS --password-stdin ACCOUNT_ID.dkr.ecr.REGION.amazonaws.com
docker build -t ACCOUNT_ID.dkr.ecr.REGION.amazonaws.com/rag-lab:latest .
docker push ACCOUNT_ID.dkr.ecr.REGION.amazonaws.com/rag-lab:latest
2

Database

Create an RDS PostgreSQL instance in private subnets (no public access). Allow port 5432 only from the app's security group.

3

Secrets

aws secretsmanager create-secret --name rag/django-secret --secret-string "$(python -c 'import secrets;print(secrets.token_urlsafe(50))')"
aws secretsmanager create-secret --name rag/database-url --secret-string "postgres://USER:PASS@RDS_HOST:5432/ragdb"
aws secretsmanager create-secret --name rag/api-key --secret-string "$(python -c 'import secrets;print(secrets.token_urlsafe(32))')"

Give the task execution role permission to read these three secrets.

4

Cluster, task and service

Edit deploy/ecs-task-def.json (account, region, domain), then:

aws logs create-log-group --log-group-name /ecs/rag-lab
aws ecs create-cluster --cluster-name rag-lab
aws ecs register-task-definition --cli-input-json file://deploy/ecs-task-def.json
aws ecs create-service --cluster rag-lab --service-name rag-lab-svc --task-definition rag-lab \
  --desired-count 2 --launch-type FARGATE \
  --network-configuration "awsvpcConfiguration={subnets=[SUBNET_A,SUBNET_B],securityGroups=[SG_ID]}" \
  --load-balancers targetGroupArn=TG_ARN,containerName=web,containerPort=8000
5

Load balancer and HTTPS

Put an Application Load Balancer in public subnets with an ACM certificate on port 443. Health check path: /healthz. Keep the tasks in private subnets. Optionally attach AWS WAF with the managed rule groups for rate limiting and common attacks.

6

Automatic deploys

In GitHub, create an IAM role that trusts GitHub's OIDC provider, then set secret AWS_DEPLOY_ROLE_ARN and variable AWS_REGION. Every push to main now tests, runs the quality gate, builds, pushes and deploys.

9. Swap the demo for real models

The demo needs no API keys. To go real, replace one stage at a time and keep the tests green:

Demo stageProduction replacement
BM25 searchEmbeddings stored in PostgreSQL with pgvector (same search() signature), combined with BM25 for hybrid search
Heuristic re-rankerA cross-encoder re-ranker model
Image and audio captionsImage embeddings (CLIP/SigLIP) and speech-to-text (Whisper or Amazon Transcribe)
Extracted sentencesAn LLM: set USE_LLM=1 and ANTHROPIC_API_KEY; the output guard still checks it
Hard-coded graphEntities and relations extracted from your documents, stored in Postgres or Neptune
Rule-based router/plannerAn LLM that returns a route or a plan as JSON

Load your own documents: split into 200 to 400 word chunks, keep the title and an acl label on each chunk, and replace the lists in rag/kb.py with a database table.

10. Troubleshooting

"Set DJANGO_SECRET_KEY" on start: export it, or set DJANGO_DEBUG=1 locally.
Pages have no styling in Docker: run collectstatic (the Dockerfile does) and keep WhiteNoise in MIDDLEWARE.
"Request blocked" on a normal question: check the Guardrails screen to see which rule fired.
ECS task keeps restarting: read the CloudWatch log group /ecs/rag-lab; the usual cause is a missing secret permission or wrong DJANGO_ALLOWED_HOSTS.
Answer says it cannot find something: the retriever did not surface the chunk; look at the trace, then add a golden question and improve retrieval.
